# 마우저(Mouser) 직소싱 대시보드 — 기획 (v0.1 · 정의 단계)

> 상태: **정의(Definition) 진행 중** — 아직 구현 시작 전. 결정 사항은 아래 §7 로그에 함께 채워갑니다.
> (대표님 로컬 `…\에듀이노_통합업무관리\마우저` 로 동기화해서 보관)

---

## 1. 배경 · 목적 (왜 하는가)

- 지금까지 라즈베리파이·Seeed 등 **테스트/개발용 부품을 디바이스마트 등에서 마진 없이** 구매해 옴.
- 앞으로는 **마우저에서 직접 소싱·구매** → ① 재고를 빠르게 확보하고 ② **마진을 남겨 회사 이익**을 늘린다.
- 이 도구는 그 의사결정을 돕는 **소싱/구매 대시보드**: "마우저 재고·가격을 자사 코드와 비교 → 판단 → 주문 → 추적".
- 핵심 가치 = **실시간 마우저 데이터 + 매끄러운 주문→추적 루프**.

## 2. 기능 플로우 (대표님 요청 원문 정리)

1. 마우저 상품코드 ↔ **이카운트 자사 상품코드** 비교, **가격 변동 일일 조사**. 마우저 상품의 **재고상태(수량)·입고일정·가격**을 확인.
2. 마우저 계정에 **즐겨찾기해 둔 카테고리**(라즈베리파이·Seeed 보드 등) 기준으로,
   `마우저코드 · 에듀이노코드 · 상품명 · 재고(있으면 수량 / 없으면 입고예정일) · 가격` 을 **한 페이지**에서 확인.
3. 제조사가 계속 추가될 예정 → **제조사별 탭 분리**.
4. 현황 오른쪽 **[결제요청] 버튼** → 누르면 (a) 프로그램 **결제요청에 리스트 추가**, (b) **마우저 장바구니에도 담기**.
5. 주문 완료 시 **주문현황 탭**에서 실시간 파악 — 마우저 주문상태 + **DHL 배송정보**(최소 DHL 추적 링크 연결).

```

마우저 탭
 ├─ 서브탭(제조사): Raspberry Pi | Seeed Studio | (추가…)
 ├─ [비교/재고 현황]  ← 메인 표
 │    컬럼: 마우저코드 · 에듀이노(이카운트)코드 · 상품명 · 제조사
 │          · 재고(수량) 또는 입고예정 · 마우저가 · (환산 원가) · 판매가/마진 · [결제요청]
 ├─ [주문현황]  ← 결제요청→주문된 건: 상태 · 수량 · 금액 · 송장 · [DHL 추적]

```

## 4. 데이터 소스 · 기술 설계 (핵심 판단)

| 기능 | 실현 방법(현실적) | 난이도/전제 |
|---|---|---|
| 가격·재고 수량·입고(리드타임) | **Mouser Search API** (`api.mouser.com`) — 서버(`api/mouser.js`)가 API 키를 들고 호출, 결과를 KV 캐시 | **API 키 필요**(무료). 클라이언트에 키 노출 금지 |
| 감시 품목 목록 | 마우저 **즐겨찾기/BOM CSV 내보내기** → 워치리스트로 등록 (또는 제조사+카테고리로 API 검색) | 즐겨찾기는 API로 직접 못 읽음 → **품번 리스트 확보 필요** |
| 이카운트(자사) 코드 매칭 | 마우저 품번 ↔ 자사코드 **매핑표**(엔티렉스 ed↔ntx 방식) | 기존 매핑표 유무 확인 필요 |
| 일일 가격/재고 변동 | **Vercel 크론**이 매일 API 조회 → 스냅샷 저장 → 변동 알림/이력 | Phase 2 |
| 결제요청 리스트 추가 | `Records.pushRaw('md','payreq', {kind:'발주',vendor:'Mouser',content,qty,amount,account})` | **바로 가능** |
| 마우저 장바구니 자동 담기 | Mouser **Order/Cart API** 또는 BOM 카트 링크 | **주문 API 접근권한 확인 필요** — 불가 시 'BOM/링크로 열기'로 대체 |
| 주문현황·DHL 추적 | Order API 상태 + `dhl.com/.../tracking?tracking-id=<송장>` 링크 | 자동상태=Order API 전제 · 최소 링크는 항상 가능 |

> **솔직한 판단.** §2의 1·2·3(비교·재고·가격·제조사탭)과 4의 "결제요청 리스트 추가"는 **확실히 구현 가능**(API 키만 있으면).
> 4의 "장바구니 자동 담기"와 5의 "실시간 주문상태 자동"은 **마우저 주문 API 권한에 달려 있어** — 확보 전까지는
> "마우저에서 열기(BOM/링크)" + "주문 수기 등록 + DHL 링크"로 **동등한 실무 흐름**을 먼저 제공하는 걸 권장.

## 5. 단계별 로드맵 (제안)

- **Phase 0 · 정의(지금)** — API 키·품목 리스트·매핑·장바구니 요건 확정. (§7)
- **Phase 1 · 조회 MVP** — `api/mouser.js` 프록시 + 마우저 탭(제조사 서브탭) + 비교표(코드·상품명·재고·가격·마진) + 워치리스트 관리 + **[결제요청] → 결제요청 리스트 추가 + 마우저 열기**.
- **Phase 2 · 일일 모니터링** — 크론 스냅샷 → 가격·재고 변동 알림/이력.
- **Phase 3 · 주문 루프** — (주문 API 확보 시) 장바구니 자동담기 + 주문현황 탭 + DHL 자동 추적.

## 6. 미결/리스크

- 마우저 API의 **입고예정일** 필드 형태(정확 날짜 vs 리드타임 주수) — 실제 응답으로 확인 필요.
- **환율/원가 환산**(USD→KRW) 기준과 **마진율** 정책 — 판매가/마진 컬럼 계산에 필요.
- 장바구니/주문 API는 **레이트리밋·인증 방식**이 검색 API와 다를 수 있음.
- 마우저 계정 로그인 세션과 우리 앱은 분리 → "우리 앱에서 그 계정 장바구니에 담기"는 API 없이는 불가.
