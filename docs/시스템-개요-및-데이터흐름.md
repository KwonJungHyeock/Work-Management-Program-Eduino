# 에듀이노 통합 업무관리 — 시스템 개요 · 데이터 파이프라인 · 검수/백업

> 프로젝트를 진행하기 전에 **"이게 어떤 기능이고, 데이터가 어떻게 흐르며, 어떻게 검수·백업되는가"** 를
> 한 장으로 설명하는 문서입니다. (코드 구조/파일 위치는 [`ARCHITECTURE.md`](ARCHITECTURE.md) 참조)

---

## 1. 무엇을 하는 프로그램인가

에듀이노 사내 업무(CS 상담 · MD 상품/발주 · 관리자 결재/현황)를 **한 화면(웹앱)** 에 모은 내부 도구입니다.
관리자가 발급한 아이디·접속코드로 로그인 → 부여된 권한대로 좌측 메뉴 사용.

| 파트 | 주요 기능 |
|---|---|
| **홈(공통)** | 홈 대시보드 · 내 업무 · 알림 · 공지사항 · 일정·달력 |
| **CS** | 상담 메모 · 견적/발주/후불 · 교환/반품/환불 · 중국 발주요청 · 답변·메일 템플릿 · 상품 조회 · 고객 정보 검색 · 파트너사 관리 · 일일결산 |
| **MD** | 입점사 발주 · 결제요청 · 입점사 관리 · 상품·품절 관리 · **가격비교(공급가 모니터링)** · TS상담 메모/검색 · 기술상담 템플릿 · 일일결산 |
| **관리자** | 결재함 · 업무 현황 · 매출 데이터 · 팀 설정(계정·권한) · 공유 범위 · 감사 로그 |

각 화면은 `window.MODULES['<파트>.<기능>']` 로 등록되고, 좌측 메뉴(해시 `#cs.notes`)로 라우팅됩니다.

## 2. 데이터 파이프라인 (전체 그림)

```
[브라우저 SPA]  ──(설정·기록 저장/조회)──▶  [/api/store]  ──▶  [Vercel KV · Redis]   ← 1차(정본) 저장소
     │  localStorage(개인설정)                (서버리스)          eduino:*  키
     │
     └──(동시 전송, 백업)──────────────────▶  [구글시트 Apps Script]                ← 2차(백업) 저장소
                                              integrations/google-apps-script/*.gs
```

- **개인 설정**은 브라우저 `localStorage`(`store()`), **팀 공용 설정·전 직원 기록**은 백엔드(`/api/store` → KV)에 저장.
- 상담/발주 등 실제 업무 기록은 저장할 때 **KV(정본) + 구글시트(백업)** 로 **동시에** 나갑니다.
- 서버 함수는 `api/` 안의 파일들뿐이고(`store`·`auth`·`catalog`·`sendmail`·`cron-sync`·`backup-snapshot`), 나머지는 정적 서빙.

### KV 키 구조 (`/api/store` 내부)

| 용도 | 키 | 방식 |
|---|---|---|
| 팀 공용 설정(범위별) | `eduino:settings` (전사) · 부서 버킷 | HSET |
| 접속자 하트비트 | `eduino:presence` | HSET(기기→시각) |
| 공용 컬렉션 | `eduino:coll:<name>` | id 기준 HSET (upsert) |
| **업무 기록(정본)** | `eduino:sheet:<부서>:<시트>:<YYYY-MM>` | id 기준 HSET · **월 버킷** |
| 담당자별 처리량 | `eduino:workstat:<부서>` · `eduino:workwho:<부서>` | HINCRBY |
| 감사 로그 | `eduino:audit` | LPUSH + LTRIM 500 |
| 월간 스냅샷 | `eduino:backup:<YYYY-MM>` · `eduino:backup:coll` | SET |

- 공용 컬렉션(`coll`) 예: `settlements`(결재/결제요청) · `notice`·`calendar`·`callbacks`(처리대기) · `ntrex`(가격변동) · `duties`·`assignments`(업무지시) · `handover_md/cs`(입점사·파트너사) · `ts_history`(TS 이력) · `chinaorders`.
- 기록 저장(`recPush`)은 `record.day`(`YYYY-MM-DD`)가 **필수** — 이 값으로 어느 달 버킷에 넣을지 결정.

### 조회 경로

- 화면 → `Records.month(부서, 시트, 'YYYY-MM')` (worklog.js) → `/api/store?type=sheet…` → 해당 월 버킷 반환.
- 여러 달을 볼 땐 월별로 조회 후 **id 기준으로 합쳐 중복 제거**.

## 3. 동작 방식 (요약)

1. **무빌드 SPA** — 빌드 과정 없이 `app.html` 이 스크립트를 순서대로 로드(데이터 시드 → 코어 → 기능 모듈 → 셸).
2. **로그인** — `api/auth.js` 가 접속코드를 서버에서 검증(코드는 클라이언트에 노출 안 됨). 역할: 대표(admin)·팀장(manager)·파트장(lead)·팀원(member).
3. **권한** — 페이지별 **[열람]/[수정]** 을 관리자가 계정에 부여. 권한 없는 메뉴는 잠금 표시. 기록 삭제는 파트장·관리자.
4. **저장** — 화면에서 저장 → `store()`(개인) 또는 `/api/store`(팀) → 필요 시 구글시트 병행 전송.

## 4. 자료 검수 (데이터 정합성 확보 방법)

프로그램이 **틀린 값이 그대로 쌓이지 않도록** 두는 장치들:

- **중복 방지 저장** — 기록/컬렉션 모두 **id 기준 upsert**(HSET). 같은 건을 여러 번 저장해도 덮어써져 중복이 안 생김.
- **월 버킷 정확성** — 저장 시 `day` 필수. 날짜(월)를 수정하면 **옛 달 버킷에서 삭제 후 새 달에 기록**해 잔재 방지.
- **가격비교 엑셀 일괄 업데이트** — 공급가표를 통으로 올리면 ①기존과 비교해 **변경분 미리보기**(신규·변경·동일) → ②**담당자 확인** 후 [최종 반영] → ③**변경이력** 자동 기록. (오반영 방지 + 근거 보존)
- **구글시트 동기화 재시도** — 전송 실패분은 `syncedAt` 미표시로 남겨 **90초 주기·재접속 시 자동 재전송**. 화면 상단에 미전송 건수 표시.
- **동시 편집 보호(lost-update 방지)** — 결제 상신 등은 저장 직전 **서버 최신 상태를 재확인**(이미 대표가 결제완료했으면 되돌리지 않음).
- **입력 서식 표준화** — 연락처는 **하이픈 자동**(010-…), 금액은 **천단위 콤마 자동**. 집계는 숫자만 추출해 합산하므로 서식이 합계를 깨지 않음.
- **감사 로그** — 기록 삭제 등 민감 동작을 `eduino:audit` 에 남겨 [관리자 → 감사 로그]에서 확인.

## 5. 백업 방식 (다중화)

데이터를 **여러 겹**으로 보관해 한 곳이 지워져도 복구되도록 설계:

| 단계 | 대상 | 방법 |
|---|---|---|
| 1차 · 정본 | 팀 공용 설정·전 직원 기록 | **Vercel KV(Redis)** — `/api/store` |
| 2차 · 병행 백업 | 상담·발주 등 업무 기록 | **구글시트**(Apps Script) 동시 전송 |
| 개인 | 기기별 설정 | 브라우저 `localStorage` |
| 수동 내보내기 | 전체 설정·데이터 | 상단바 **[설정 백업]** → `.json` 파일 저장/복원(PC·직원 간 공유 겸용) |
| 정기 스냅샷 | 그 달 전체 기록·컬렉션 | **월간 스냅샷**(`api/backup-snapshot`) → `eduino:backup:<월>` 에 통째로 복사(편집·삭제로부터 보호) |

### 자동 실행(크론 · `vercel.json`)

- **매일 15:00(UTC)** — `api/cron-sync` : 구글시트 정기 동기화.
- **매월 1일** — `api/backup-snapshot` : 지난달·이번달 스냅샷 저장(`eduino:backup:index` 로 이력 관리, `eduino:backup:meta` 에 마지막 백업 시각).

## 6. 한 줄 요약

> **입력 → (검수: 미리보기·확인·서식·중복방지) → KV(정본) + 구글시트(백업) 동시 저장 →
> 매일 시트 동기화·매월 스냅샷으로 다중 백업.** 화면은 무빌드 SPA로 모듈 등록만 하면 붙습니다.
